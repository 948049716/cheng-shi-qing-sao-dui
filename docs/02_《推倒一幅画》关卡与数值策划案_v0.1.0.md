## 1. 关卡设计总目标与数值原则

本策划案为《推倒一幅画》**连续单线关卡体系与全盘数值的单一事实来源**，服务于手工精调、离线程序化生成（`tools/generate-levels.mjs`）以及上线后的关卡热更调优。

1. **解压优先、思考托底**：所有关卡必须让玩家体会到「推一下、倒一片」的连锁爽感，绝不出现零散逐块点推的垃圾时间；思考点集中在「推哪块 × 往哪推 × 先推谁」，而非复杂算术。
2. **连续单线、波浪心流**：采用从第 1 关持续向后编号的单线序列，每 `5` 关固定组成一轮 **「易 → 易 → 中 → 难 → 爽」** 心流循环，在轻度卡点之后立即用高连锁奖励关释放压力。
3. **求解器兜底、拒绝无效关卡**：每关上线前必须通过离线求解器严格证明 `limit` 推可解且 `limit - 1` 推无解，并满足每推最小覆盖率与顺序依赖阈值。
4. **数值零付费墙**：不设体力、不设限时倒计时、撤销永久免费；广告与收集数值围绕「卡关轻辅助」与「完美收集」展开，绝不破坏解压基调。

## 2. 关卡难度量化模型（四档精确定义）

为避免关卡难度只靠网格大小粗放划分，系统用 **5 个可由求解器离线计算的量化指标** 定义关卡真实难度：

| 指标代号 | 指标名称 | 计算定义 | 玩家体感映射 |
| :---: | :--- | :--- | :--- |
| **`L`** | **最少推力** | 求解器证明的最小通关推数（`1～5`） | 决策步数与整体思考跨度 |
| **`O`** | **顺序依赖度** | 将标准解 `sol` 的 `L` 推任意重排（`L!` 种顺序），因「已倒即挡」导致失败的排列占比（`0%～100%`） | 是否需要仔细判断「先推谁、后推谁」 |
| **`S`** | **首推容错率** | 棋盘全部合法首推中，存在后续 `L - 1` 推通关解的起手占比 | 找到「关键第一推」的直觉难度 |
| **`P_spec`** | **特殊牌占比** | `(转向牌 + 分岔牌 + 进阶机关) / 有效骨牌总数` | 棋盘视觉复杂度与路线分支密度 |
| **`C_max` / `C_min`** | **最大 / 最小单推覆盖率** | 标准解中单推倒下块数占总骨牌数的最高 / 最低比例 | 连锁爽感峰值与收尾饱满度 |

### 2.1 四档难度量化标准表（供生成器筛选）

| 难度档位 | 心流定位 | 推力 `L` | 顺序依赖 `O` | 首推容错 `S` | 特殊牌占比 `P_spec` | 单推覆盖约束 | 预期单局时长 |
| :---: | :--- | :---: | :---: | :---: | :---: | :--- | :---: |
| **易** | 顺手破局、快速建立节奏 | `1～2`（后期 `2～3`） | `0%～20%` | `≥ 12%` | `10%～22%` | `C_min ≥ 18%` | `25～50 秒` |
| **中** | 看清路线、1～2 次撤销过关 | `2～3`（后期 `3～4`） | `20%～55%` | `5%～15%` | `15%～26%` | 常规 `C_min ≥ 15%` | `1～2 分钟` |
| **难** | 明确「已倒即挡」博弈，有破局成就感 | `3～5` | `≥ 50%` | `1%～8%` | `18%～30%` | 常规 `C_min ≥ 15%`（异形 `≥ 10%`） | `2～4 分钟` |
| **爽（逢 5 关）** | 大连锁倾泻、音阶拉满的奖励关 | `1～2` | `≤ 20%` | `≥ 15%` | `16%～28%`（高分岔） | **`C_max ≥ 60%`** 且链深 `≥ 12` 层 | `20～45 秒` |

> [!NOTE]
> 对「爽」关额外要求**最长单推 BFS 链深 ≥ 12 层**，确保加速间隔从 `130ms` 顺滑压低至 `42ms` 并将 G 调五声音阶完整拉升至高音区，配合 `≥ 40` 连击触发「超级连锁！」与牌桌震动。

### 5.2 像素画入库 5 条可玩性红线（入生成器前自动拦截）
1. **零孤岛原则**：像素画中禁止出现四邻域全为空位的 1 格孤立像素（会迫使玩家白耗 1 点推力推 1 块）；全图正交连通分量数量必须 `≤ 目标推力 L`（爽关强制要求全图单连通分量）。
2. **有效填充率**：有效像素格数占外接矩形 `W × H` 的 **`45%～85%`**。低于 45% 会形成过多细长枝杈难以分岔，高于 85% 失去异形画作轮廓趣味。
3. **色彩克制与聚片**：统一使用 [06_像素画与骨牌渲染实现方案](06_《推倒一幅画》像素画与骨牌渲染实现方案_v0.1.0.md) §2.2 的十色调色板，单幅画使用 `2～5` 种颜色；同色像素尽量成片聚合，保证翻色过程中画面一眼可辨。
4. **窄颈上限**：1 格宽且长度 `≥ 3` 的细长臂（如细尾巴、细天线）单幅画不超过 `2` 处，避免过度压缩可用起点。
5. **命名可读性**：画名控制在 `2～4` 个中文常用字，配 1 枚精准辨识图标（emoji 或像素小图），保证通关揭晓瞬间的「啊，原来是这个！」惊喜感。

## 6. 程序化关卡生成参数与求解器策略

衔接 [04_技术架构与开发手册](04_《推倒一幅画》技术架构与开发手册_v0.1.0.md) §5，离线生成器按以下数值参数批量生产并自动分级：

### 6.1 牌型生成决策权重表
当正向模拟连锁踏入尚未定型的格子 `(y, x)`（前方空闲=`f`，左/右空闲=`l`/`r`）时，按以下权重决定牌型：

| 邻格空闲态势 | 易 / 爽关权重 | 中 / 难关权重 | 说明 |
| :--- | :--- | :--- | :--- |
| **`f` 空闲，且 `l` 与 `r` 均空闲** | 分岔 `16%` / 转向 `12%` / 普通 `72%` | 分岔 `10%` / 转向 `18%` / 普通 `72%` | 爽关提高分岔率制造大面积开花 |
| **`f` 空闲，仅 `l` 或 `r` 之一空闲** | 转向 `14%` / 普通 `86%` | 转向 `20%` / 普通 `80%` | 适度拐弯避免全是直线 |
| **`f` 受阻，`l` 与 `r` 均空闲** | 分岔 `65%` / 转向 `35%` | 分岔 `50%` / 转向 `50%` | 撞墙自动引流，维持链路连贯 |
| **`f` 受阻，仅 `l` 或 `r` 之一空闲** | 转向空闲侧 `100%` | 转向空闲侧 `100%` | 沿画作边缘顺滑折返 |
| **三向均受阻** | 普通 `100%` | 普通 `100%` | 链路自然收尾 |

### 6.2 进阶机关注入配额上限

| 机关类型 | 单关数量建议 | 生成器注入与安全约束 |
| :--- | :---: | :--- |
| **重骨牌（`×2`）** | `1～5` 块 | 仅注入在「被标准解至少 2 条不同支路/推次经过」的交叉格上，天然保证可破甲 |
| **弹簧牌** | `1～3` 块 | 仅放置在来向反方向仍有未倒骨牌的端点；禁止两块弹簧牌直接相对形成无限往返 |
| **彩色闸门** | `1～2` 组（每组 `1～2` 格） | 绑定颜色的像素总数占全图 `10%～25%`；求解器校验开门顺序必存在合法前置推 |
| **桥牌** | `1～2` 块 | 放置于两推轨迹交叉点；单次连锁中同一桥牌最多被穿越 `4` 次，全局步数上限 `256` 防死环 |
| **定时牌** | `1～2` 块（`N ∈ {1, 2}`） | 仅用于消除两路在交叉点的时间竞争，由模拟层按 `layer + N` 分桶确定性结算 |

### 6.3 最少推力证明与大关求解性能策略
1. **深度 `1～3`（`L ≤ 4`）**：直接使用标准 BFS 按状态串 `fallen.join('')` 去重穷举验证 `L - 1` 推无解，单次状态预算上限 `400,000`。
2. **深度 `4`（`L = 5` 高阶关）**：对合法动作先按「倒下块数降序」做等价状态剪枝（忽略仅倒 1 块且不触发任何机关的无效微推），状态预算上限 `600,000`；若单种子求解超时（`> 3s`）则丢弃该种子换下一个种子，确保入库关卡 **100% 经过严格证明而非近似估算**。
