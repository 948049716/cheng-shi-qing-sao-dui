## 1. 版本号格式：`vX.Y.Z`

本项目所有正式文档统一采用三段式语义化版本号 **`vX.Y.Z`**（主版本号.次版本号.修订号）：

| 字段 | 名称 | 递增规则 | 典型触发场景 |
| :---: | :--- | :--- | :--- |
| **`X`** | **主版本号** | `0` 表示正式上线前的立项、原型与测试阶段；`1` 表示首发上线基线版本；上线后仅在核心玩法大重构或资料片级大改版时递增，同时将 `Y`、`Z` 归零。 | `v0.1.0`（立项定稿）→ `v1.0.0`（首发上线）→ `v2.0.0`（大改版） |
| **`Y`** | **次版本号** | 新增完整玩法系统、新骨牌/机关模块、大段关卡规划或重大规则结构调整时递增，同时将 `Z` 归零。 | `v0.1.0` → `v0.2.0`（新增重骨牌与弹簧牌机制） |
| **`Z`** | **修订号** | 单项数值微调、边界规则补漏、错别字或表述优化、同步线上热更参数时递增，不改变文档核心结构。 | `v0.2.0` → `v0.2.1`（调整连锁间隔参数或补充边界场景） |

## 4. 文档编写与迭代维护红线

1. **三处版本号强一致**：同一文档的**文件名**、**顶部属性表**、**文末版本修订记录最新一行**三处版本号必须严格一致。
2. **立项初稿不虚升版本号**：单份文档在首次正式签发归档（或研发采纳）前的连续打磨修改，统一维持 **`v0.1.0`**；仅在正式签发定版后发生的新增需求或后续研发迭代，才按 `vX.Y.Z` 递增。
3. **正文纯净原则**：文档正文只保留**当前最新生效的设计口径**，严禁夹杂废弃旧方案对比、过程讨论痕迹、口语化批注或临时草稿说明。
4. **单一事实来源**：跨文档引用同一规则或数值时，只在一个主文档中定义完整细节，其余文档注明参见对应编号文档，避免多处复制导致数值打架。
5. **代码与文档同步**：进入研发阶段后，任何影响玩家体验的规则改动或数值热更，合入主干前必须同步更新对应文档并递增 `Z` 或 `Y` 版本号。
6. **归档管理**：历史旧版本文件移入 `archive/` 归档目录（或以 git 历史留存），当前活跃目录每个编号只保留最新生效的一份文档。
