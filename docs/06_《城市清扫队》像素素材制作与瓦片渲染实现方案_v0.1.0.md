## 1. 核心目标与设计原则

在《城市清扫队》中，玩家看到的是**连绵起伏的星露谷风冬季街雪、紧贴建筑墙根的自然雪坡、波浪垂雪盖住的纸箱与冰块**；但在玩法底层，工程车必须按严格的正交网格 **1 格 1 格精准铲除**。

本文档定义如何以**极低的美术制作量**与**极轻的微信小游戏包体（核心图集 ≤ 65 KB）**，实现高精致度的动态逐格铲雪表现：

1. **视觉有机连贯、逻辑严格分格**：连续材质采用 **「四象限自动拼接（Quarter-Tile Autotile）」**，每类材质只需画 **5～6 张基础母图**，运行时即可自动拼合全部 **47 种**外凸圆角、直边雪崖、内凹转角与十字交叉形态。
2. **叠层实时组合、拒绝排列组合死图**：双层障碍（同色 `×2` 与异色「雪下藏垃圾 / 雪压冰」）全部在渲染层通过**底座 + 表层叠加贴图**动态组合，新增障碍品类时无需成倍增加贴图。
3. **建筑与积雪解耦**：建筑本体只画暗/亮两态干净贴图；墙根堆雪与屋檐冰凌作为独立 **接触贴花（Contact Decal）** 随相邻网格状态实时消融。
4. **局部脏矩离屏缓存**：仅在车辆铲除某一格的瞬间，重算该格与周围 8 邻域（共 `3×3` 格）的拼接索引并局部重绘离屏障碍画布，确保中低端手机稳跑 **60 FPS**。

## 2. 像素视觉规范与星露谷暖调色板

### 2.1 全局像素尺度与防糊边铁律
- **视角锁定**：严格 **90° 正交顶俯视角**，禁止任何斜 45° 等距变形或透视拉伸。
- **统一逻辑格尺度**：**`16 × 16` 逻辑像素 = 1 逻辑格**（所有障碍瓦片、碎石板地砖、墙根贴花均按此网格对齐，杜绝“混合像素大小 / Mixels”）。
- **跨格元素基准**：工程车 `24 × 24 px`、复古路灯 `12 × 26 px`、漫步像素居民 `12 × 20 px`、嵌入式微缩建筑占 `2×2` / `3×2` / `5×2` 逻辑格（屋顶允许向上溢出 `4～10 px` 增强立体层次）。
- **渲染清晰度**：Canvas 强制 `ctx.imageSmoothingEnabled = false`，绘制坐标统一 `Math.round()` 整数像素吸附；合图内所有平铺瓦片与象限块四周施加 **`1px` 边缘像素外扩（Extrusion）**，彻底消灭缩放接缝渗色。

### 2.2 星露谷冬季色相偏移色板（Master Palette）
采用「亮部偏暖奶油、暗部偏冷蓝紫/深棕、描边统一暖深棕 `#3a2117`」的色相偏移（Hue-Shifting）规范，彻底避免脏灰与纯黑生硬感：

| 元素类别 | 高光（Highlight） | 主色（Base） | 暗面/雪崖（Shade） | 外轮廓（Outline） | 表面像素纹样特征 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **建筑统一描边 / 木构** | `#d69c5a` | `#a86a34` | `#75421b` | `#3a2117` | 暖橡木框、横向木板纹、石砌地基、屋瓦阶梯高光 |
| **白松雪（White Snow）** | `#fffef9` | `#f4f7fc` | `#b3c6df` | `#465872` | 蓬松弧形雪丘波纹、浅蓝雪褶、细碎白晶亮点 |
| **蓝冻冰（Glacial Ice）** | `#dcf8ff` | `#64c6ea` | `#2a85b5` | `#1d486b` | 45° 阶梯玻璃高光斜纹、硬朗冰裂痕、钻石光点 |

## 3. 障碍物与场景贴图分类设计规范

### 3.1 连续铺面类（白松雪 / 蓝冻冰 / 紫深霜 / 棕雪泥）：四象限自动拼接（Autotile）

连续堆积物必须能自然融成一整片并在被铲出缺口时自动圆角收边。每类连续材质**无需手画 47 张整格图**，只需制作 **1 张 `80 × 16 px` 的 5 块母图模板条（外加 2 张中心变体）**：

```text
母图条布局（单格 16×16，程序自动按 8×8 切为 NW/NE/SW/SE 四个子象限）：
+--------+--------+--------+--------+--------+  +--------+--------+
| Tile 0 | Tile 1 | Tile 2 | Tile 3 | Tile 4 |  | Var A  | Var B  |
| 孤立块 | 中心满 | 水平边 | 垂直边 | 内凹角 |  | 纹理1  | 纹理2  |
+--------+--------+--------+--------+--------+  +--------+--------+
  外凸圆角   全实心   上下直边  左右直边  L形内拐     消除大面积平铺重复
```

**5 块母图绘制细则（`16 × 16 px`）**：
1. **`Tile 0`（孤立小堆 / 外凸四圆角）**：四角均做 `2px` 阶梯圆角收边，北缘 `2px` 亮高光，南缘 `3px` 深色立体雪崖立面 + `1px` 轮廓与下方 `2px` 透明地面投影。程序切取其 4 个 `8×8` 角即得所有**外凸圆角**。
2. **`Tile 1`（全实心平铺底）**：四边无缝延续，画基础色调与微弱雪波/冰纹。
3. **`Tile 2`（上下外露水平直边）**：左右无缝延续，北边画 `2px` 亮雪脊，南边画 `3px` 立体雪崖 + 投影。
4. **`Tile 3`（左右外露垂直直边）**：上下无缝延续，左右两侧各留 `1px` 外缘轮廓与柔和侧影。
5. **`Tile 4`（内凹转角补丁）**：四角内侧各画一个 `3×3 px` 的柔和凹角过渡阴影与边缘收口（当相邻的横、纵两格都有同类雪，但斜角那格被铲空时自动贴上，让缺口呈现平滑圆弧而非生硬直角）。
6. **`Var A / Var B`（内部细节变体 ×2～3）**：用于铺在完全被包围的内部实心格中（如紫霜里的像素雪花、蓝冰里的斜向冰裂、白雪里的风吹雪丘、雪泥里的碎石），通过格子坐标哈希确定性选用。

### 3.2 独立物件类（废纸箱 / 断枝堆 / 后期落叶袋等）
独立堆积物天然呈颗粒状堆放，**不启用 47 态拼接**：
- 每类仅制作 **3～4 张 `16 × 16 px` 独立变体贴图**（改变盒盖角度、蝴蝶结位置、枝干朝向与积雪厚薄），底部自带 `2px` 半透明暖棕投影。
- 当同类独立物件紧挨着铺放时，借助轻微的 `±1px` 视觉重心错位与变体哈希，自然呈现热热闹闹的集市堆叠感。

### 3.3 双层障碍叠层贴图（同色 `×2` & 异色「雪下藏物」）
所有双层格均通过**双层实时叠加**实现，杜绝排列组合爆炸：

1. **同色双层（如厚白雪 `×2`、厚蓝冰 `×2`）**：
   - 每类连续材质额外制作 **1 张 `14 × 12 px` 透明底「加厚雪冠 / 冰脊凸起」贴图**（自带底部 `2px` 压暗阴影）。
   - 绘制时先正常渲染底层单层 Autotile，再将雪冠贴图居中并向上偏移 **`3px`** 叠加，右上角叠加 `5×5 px` 金色像素角标。
   - 第一辆车铲除表层时，仅播放雪冠碎裂动画并移除雪冠，底层保持完好无跳变。
2. **异色双层（如「白雪盖红纸箱」「白雪盖绿断枝」「白雪盖蓝冰」）**：
   - 全游戏只需制作 **2～3 张通用的 `16 × 13 px`「波浪垂雪被（Snow Cap Overlay）」透明贴图**：上半部为饱满蓬松白雪，下沿呈有机波浪雪檐并带 `1px` 下落投影，仅覆盖格子上半 `60%～65%`。
   - 绘制时：**先完整绘制里层物件（纸箱/断枝/冰块）→ 再叠加波浪垂雪被 → 右上角叠加 `5×5 px` 里层颜色微标**。下半截 `35%` 真实露出纸箱红底与金丝带，玩家一眼即可判断「雪下面藏着什么」。

### 3.4 建筑本体与墙根自然堆雪贴花（Contact Decal）
为了使雪自然“靠”在房屋墙脚与门阶上，而又不把雪画死在建筑图里：

| 贴图组件 | 数量与尺寸 | 触发与消融逻辑 |
| :--- | :--- | :--- |
| **建筑本体（暗态 / 暖灯态）** | 每栋建筑 2 张整图（如 `32×38` / `48×42` / `80×42 px`，屋顶含固定顶雪与向上溢出） | 门口触发格未清够数量时绘**暗态**；达标瞬间切换**暖灯态**并叠加径向暖金光晕与居民走出 |
| **南侧墙根雪坡贴花** | 每种连续材质 2 张 `16 × 6 px` 透明弧形雪坡（可做白雪灰度版 + 运行时染色复用） | 遍历建筑正南紧邻的每一格，若该格存在障碍，则在建筑底墙上爬 `3～5 px` 叠画对应材质的斜坡堆雪；该格一铲除，该段墙脚堆雪即刻消失 |
| **东西侧墙风吹雪坡** | 2 张 `4 × 16 px` 左侧/右侧渐薄雪坡 | 检查建筑左右两侧紧邻格，若有障碍则紧贴侧墙边缘叠画，消除墙体与雪原间的直线割裂感 |
| **屋檐像素冰凌** | 2 张 `16 × 5 px` 冰凌串变体 | 仅在建筑处于**暗态（未通暖灯）**时叠加在屋檐下沿；亮灯后平滑淡出 |

### 3.5 车辆、机关与星露谷风 UI 资产规格
- **工程车 / 垃圾车（`24 × 24 px`）**：每类车只需 **3 个朝向 × 2 帧驱动动画 = 6 帧**（向右行驶 2 帧，向左通过水平镜像 `scale(-1, 1)` 复用；向上背面 2 帧；向下正面 2 帧），另配 1 套金橙色 **三合一烈焰巨兽** 6 帧与 1 套彩虹 **万能车** 6 帧。
- **机关元件（`16 × 16 px`）**：暖气总阀（关闭红阀 / 开启金阀 2 帧）、冰封门（带竖向冰栅栏，2 帧微闪）、地下暖气铜管（横/竖/弯头暗纹贴花）。
- **星露谷木框 UI（九宫格切图 9-Slice）**：
  - 雕花暖橡木外框（`24×24` 九宫格，四角带木钉与高光斜边）；
  - 暖奶油羊皮纸卡片底（首排亮卡 / 2~3 排暗卡 / 冰封 `❄×N` 蓝霜遮罩 / `?` 深靛盲盒底）；
  - 雪顶木屋车库顶棚饰片（`44×14 px` 独立盖在每个常驻车位顶部，配合空位木门底纹与 `P+1` 虚线木框）。

## 4. 标准化素材生产与自动化入库管线

衔接 [04_技术架构与开发手册](04_《城市清扫队》技术架构与开发手册_v0.1.0.md) §3.3，素材生产分为 **3 个严格解耦阶段**：

### 4.1 阶段一：风格锚定与大件制作（AI 生图 / Aseprite 精修）
- 以 [03_局内设计图集](03_《城市清扫队》局内设计图集_v0.1.0.md) 中的 4 张星露谷风局内稿作为唯一视觉锚点。
- **大件叙事资产**（10+ 座主题建筑暗/亮双态、雪国火车站与铁轨、雪松边景、通关明信片底图、道具徽章）可由 AI 生图或像素画师在 Aseprite 中绘制，再进入阶段三自动化归一化。

### 4.2 阶段二：高频规则瓦片制作（Aseprite 逐像素绘制 / 代码像素烘焙）
- **连续铺面 5 块母图、独立垃圾变体、垂雪被、墙根贴花、车辆 6 帧** 必须严格对齐 `16×16` / `24×24` 像素网格，严禁直接从整图硬裁导致边缘像素错位。
- MVP 阶段可由 `tools/pixel-baker.mjs` 按限定色板直接程序化烘焙出可运行的标准图集；量产阶段由像素美术在 Aseprite 中按相同 `atlas_core.json` 格位逐张替换，**客户端代码零改动即可完成画面升级**。

### 4.3 阶段三：自动化像素归一化与打包门禁（`tools/asset-pipeline.py`）
所有原稿放入 `assets-raw/` 后统一过脚本流水线输出到 `minigame/assets/`：
1. **真透明检测**：拦截带伪棋盘格底纹或半透明脏边（Alpha 在 `1..254` 的边缘糊点）的素材，强制二值化边缘透明通道。
2. **最近邻整数对齐与限色调色板量化**：按目标像素尺寸执行 Nearest-Neighbor 缩放，并吸附至 `master-palette.json` 对应色板。
3. **`1px` 边缘像素外扩（Extrusion）**：为每个瓦片与象限块外圈复制 `1px` 边缘色，彻底杜绝 Canvas 缩放时相邻图块渗色（Texture Bleeding）。
4. **图集合并与体积校验**：打包输出 `atlas_core.png` + `atlas_core.json`，使用索引色（PNG-8）无损压缩并校验主包体预算。

## 5. 游戏内动态逐格铲雪与渲染工程实现

### 5.1 逻辑网格数据与象限拼接缓存
每格只需维护极轻量的状态，完全不影响 BFS 寻路与核心数值校验：

```javascript
// 单格逻辑与视觉缓存结构
const cell = {
  type: 'OBS',              // 'EMPTY' | 'OBS' | 'BLDG' | 'GATE'
  layers: [0, 5],           // 栈底=里层(如5=红纸箱)，栈顶=当前表层(如0=白松雪)
  quads: [0, 0, 0, 0],      // 缓存 NW/NE/SW/SE 四个 8×8 子象限的母图索引 (0..4)
  variant: 0,               // 确定性哈希变体索引：(r * 73 + c * 37) % 3
  wipe: null,               // 正在被车铲削的过渡动画：{ dir, progress: 0..1, layerKind }
};
```

### 5.2 四象限 Autotile 核心查表算法

将连续材质的相邻判断封装为 `computeCellQuads(grid, r, c)`。关键技巧：**把建筑格 `BLDG` 与相邻同类障碍格一并视为“无缝贴靠”**，这样雪坡就会严丝合缝顶进墙角，不留 `1px` 缝隙：

```javascript
// 子象限形态枚举：对应母图条中的 Tile 0..4
const QUAD = { OUTER: 0, FULL: 1, EDGE_H: 2, EDGE_V: 3, INNER: 4 };

// 计算单个 8×8 子象限形态：h=横向邻格是否连通, v=纵向邻格是否连通, d=斜角邻格是否连通
function resolveQuad(hasH, hasV, hasDiag) {
  if (!hasH && !hasV) return QUAD.OUTER;   // 外凸圆角（暴露于已清通街面）
  if (hasH && !hasV)  return QUAD.EDGE_H;  // 水平直边（露出北雪脊或南雪崖）
  if (!hasH && hasV)  return QUAD.EDGE_V;  // 垂直直边（露出左或右外轮廓）
  return hasDiag ? QUAD.FULL : QUAD.INNER; // 横纵均连通：斜角有雪则全实心，斜角被铲空则画内凹转角！
}

function computeCellQuads(grid, r, c) {
  const cell = grid[r][c];
  if (cell.type !== 'OBS') return;
  const topKind = cell.layers[cell.layers.length - 1];

  // 同类障碍 OR 紧邻建筑墙体，均视为无缝贴靠
  const link = (rr, cc) => {
    const nb = grid[rr]?.[cc];
    if (!nb) return false;
    if (nb.type === 'BLDG') return true;
    return nb.type === 'OBS' && nb.layers[nb.layers.length - 1] === topKind;
  };

  const n = link(r - 1, c), s = link(r + 1, c);
  const w = link(r, c - 1), e = link(r, c + 1);
  const nw = link(r - 1, c - 1), ne = link(r - 1, c + 1);
  const sw = link(r + 1, c - 1), se = link(r + 1, c + 1);

  cell.quads[0] = resolveQuad(w, n, nw); // NW 左上 8×8
  cell.quads[1] = resolveQuad(e, n, ne); // NE 右上 8×8
  cell.quads[2] = resolveQuad(w, s, sw); // SW 左下 8×8
  cell.quads[3] = resolveQuad(e, s, se); // SE 右下 8×8
}
```

### 5.3 逐格铲除时的「裁剪推平 + 粒子 + 3×3 脏矩重绘」时序

为彻底消除格子“瞬间凭空消失”的廉价感，车辆清扫单格按以下 3 步闭环执行：

1. **切入推平阶段（`0 ~ 0.12s`）**：
   - 铲车抵达目标格 `(r, c)` 边界时，在动态层为该格挂起 `wipe = { dir, progress: 0, kind }`，同时将离屏障碍画布中 `(r, c)` 的表层先清掉（若为双层格，此时离屏画布已经直接露出干净的里层！）。
   - 在动态层绘制该表层瓦片时，使用 `ctx.save() → ctx.beginPath() → ctx.rect(...) → ctx.clip()`，按 `dir`（`up/down/left/right`）与 `progress` 实时缩减裁剪矩形，呈现**雪块顺着铲斗推进被一点点推薄削平**的解压动效。
   - 同步从固定容量对象池（256 槽、`swap-remove` 零 GC）沿车头斜前方喷出 `6～8` 颗同色 `2×2 px` 像素雪渣/冰晶/纸屑粒子。
2. **结算与 8 邻域自动圆角收边（`progress >= 1.0`）**：
   - 弹出 `cell.layers` 栈顶并释放 `cell.wipe = null`。
   - 仅遍历 **`(r - 1 .. r + 1, c - 1 .. c + 1)` 共 9 个格子**：调用 `computeCellQuads()` 重算邻格的 4 象限掩码，并在离屏障碍画布 `offObsCtx` 上只对这 `3×3` 矩形执行 `clearRect` + 重绘。
   - 原本连成整片的雪原会瞬间在被铲位置**自动生成圆润内凹转角与南侧 3D 雪崖切面**。
3. **建筑墙根消融与暖灯联动**：
   - 若 `(r, c)` 紧邻某栋建筑的南/西/东墙，因该格已变空，下一帧绘制建筑层时自动跳过该段的墙根堆雪贴花；
   - 若该建筑关联的门口触发格全部清通，自动隐藏屋檐冰凌、将建筑切为暖灯亮窗贴图，按五声音阶播放风铃音效并派出漫步像素居民。

### 5.4 六层渲染流水线与无缝长卷衔接

与 [04_技术架构与开发手册](04_《城市清扫队》技术架构与开发手册_v0.1.0.md) §5.1 严格一致，每帧按固定 6 层由底到顶绘制（单帧耗时 `< 4 ms`）：

| 层级 | 渲染内容 | 缓存与性能策略 |
| :---: | :--- | :--- |
| **Layer 0** | 天空氛围（晨雪 / 昭和黄昏 / 深靛星夜）、远景飘雪、顶部与底部雪松林边景 | 纯静态或极低频动画，按视口裁剪 |
| **Layer 1** | 连续碎石板街面、地下暖气铜管暗纹、南侧贯通车行大道与区界斑马线 | **`OffscreenCanvas` 静态缓存**，开局仅绘制 1 次 |
| **Layer 2** | 障碍格层（连续材质 4 象限 Autotile、独立垃圾变体、同色 `×2` 雪冠、异色波浪垂雪被、冷调未达阴影与前排暖光呼吸边） | **`OffscreenCanvas` 局部脏矩缓存**，仅在铲格/机关变化时重绘 `3×3` 脏区域 |
| **Layer 3** | 嵌入式建筑本体（暗/亮双态）→ 墙根堆雪 & 屋檐冰凌贴花 → **按 Y 坐标排序的动态对象**（四方向工程车、漫步像素居民、街灯及暖金光晕） | 每帧动态绘制（建筑本身仅 1 次 `drawImage`，无复杂路径计算） |
| **Layer 4** | 正在被铲削的表层 `wipe` 裁剪动画、对象池雪雾/碎冰/火花粒子、火焰弹 3×3 瞄准光圈与飘字 | 固定容量对象池，运行期 0 内存分配 |
| **Layer 5** | 星露谷雕花木框 HUD、5+1 雪顶车库、4×3 羊皮纸队列与底部 4 枚金边道具栏 | 脏标驱动重绘，仅状态变更时更新 |

**无缝长卷 0 缝隙过渡实现**：
- 每个街区宽 `stride = 17 × 16 = 272 px`（左右 0 留白边缘直连），局内固定 `camX = activeIdx` **严格禁止手动拖拽**。
- 通关进入下一街区时，`targetCamX = activeIdx + 1`，镜头以平滑缓动右移；渲染器做视口剔除，仅绘制当前区与相邻 1 个街区，在两区交界 `seamX` 处叠加 `2px` 浅石缝与南侧人行横道斑马线，实现浑然一体的城市长卷漫游感。
