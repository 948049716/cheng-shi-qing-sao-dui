## 1. 核心目标与渲染设计原则

在《推倒一幅画》中，解压感的视觉核心来自两件事：**一推倾泻的流畅倒牌节奏**，以及**米白骨牌逐块翻成鲜明像素画的瞬间变化**。同时，关卡数量可达数百关，不能为每幅像素画单独切整张大图。

本文档定义如何以**极小的包体开销（核心视觉资产 ≤ 40 KB）**与**极高的渲染帧率（中低端手机稳跑 60 FPS）**，在微信小游戏原生 Canvas 2D 中高质量落地：

1. **骨牌预烘焙、零逐帧阴影开销**：所有站立骨牌牌型（普通/转向/分岔/进阶机关）在开局按当前格宽 `cellSize` 一次性预烘焙到离屏图集，对局中仅执行轻量 `drawImage`，杜绝移动端每帧计算圆角渐变与多层 `shadowBlur` 掉帧。
2. **像素画全程序化色板着色**：每幅像素画在关卡 JSON 中仅为几十字节的色码字符矩阵，运行时查统一调色板绘制圆角微立体瓷砖，百关画作零图片包体增长。
3. **动态仅画活跃帧、静态全进离屏缓存**：牌桌底板与已倒落定的像素画瓷砖分别驻留离屏画布，只有正在倒下的活跃骨牌（通常同屏 1～15 块）与扬尘粒子走每帧动态更新。
4. **皮肤与音色解耦热切**：骨牌背面纹样、牌桌材质通过皮肤配置表切换，仅重烘焙一次离屏骨牌图集即可全盘生效，零逻辑改动。

### 2.3 进阶机关视觉规格（21 关起逐步登场）

| 机关类型 | 牌身底色 | 标志性视觉要素 | 状态变化动画 |

| **弹簧牌** | 浅紫 `#f5f0ff → #ded2fa` | 中央紫色回弹弹簧图标 | 被撞时沿来向压缩 `20%` 再弹回原位并反向推出连锁 |

## 3. 骨牌离屏预烘焙方案

每次进入关卡并确定 `cellSize`（`24～58px`）后，渲染器在 `1ms` 内一次性将当前皮肤所需的站立骨牌 sprite 预烘焙到一张小离屏画布（`dominoCacheCanvas`）：

```text
dominoCacheCanvas 槽位布局（单槽 stride = cellSize + 8px，预留投影出血区）：
+--------+--------+--------+--------+--------+--------+--------+
| NORMAL | TURN ^ | TURN > | TURN v | TURN < | SPLIT  | PRESS  |
+--------+--------+--------+--------+--------+--------+--------+
| HEAVY2 | HEAVY1 | SPRING | BRIDGE | GATE   | TIMER  | ...    |
+--------+--------+--------+--------+--------+--------+--------+
```

* **清晰度保障**：离屏画布按 `stride * dpr` 分配物理像素，使用 Canvas 2D 矢量路径绘制圆角牌面、顶高光、底面厚度、投影与居中矢量符号，保证在任意 `cellSize` 与手机 DPR 下边缘锐利无锯齿。
* **性能收益**：棋盘上最多 `12×12 = 144` 块骨牌，每帧仅做若干次整数坐标 `drawImage`，彻底消除每帧重复创建渐变与模糊阴影的开销。

## 4. 倒牌连锁动效与粒子演出规范

倒牌动画是本作解压手感的关键，严格采用**「两段衔接 + 方向性挤压拉伸」**模型（总时长 `230ms`），杜绝「原地渐隐切换」的僵硬感：

### 4.1 单块骨牌倒下时间轴（已知倒向向量 `(dx, dy)`）

| 时间段 | 动画主体 | 变换轨迹 | 缓动曲线 |
| :---: | :--- | :--- | :--- |
| **`0～150ms`** | 站立牌身幽灵层 | 从 `(0, 0)` 沿 `(dx, dy)` 滑出 `45%` 格宽；沿倒向轴压扁至 `0.35×`、垂直轴微拉至 `1.15×`，透明度 `1 → 0` | `ease-in`（模拟重力加速倾倒） |
| **`0～230ms`** | 彩色像素瓷砖正面 | 从 `(dx×40%, dy×40%)` 且沿倒向拉伸 `1.35× / 0.75×`、透明度 `0.3` 弹入；`60%` 处过冲放大至 `1.08×`；`100%` 落定回 `1.0×` 并烘焙进静态瓷砖离屏层 | `ease-out` |
| **`0～320ms`** | 扬尘粒子（3 粒） | 在撞击落点 `(cx + dx×0.5w, cy + dy×0.5h)` 沿随机角度叠加倒向惯性飞散 `6～16px`，`5×5px` 米白圆角尘点缩至 `0.3×` 淡出 | 线性减速 |

### 4.2 全局连锁庆祝与通关演出
1. **实时连击浮字**：连锁每落 1 块更新顶部 `×N`，附带 `120ms` 缩放弹跳 `1.35 → 1.0`；连锁结束达到 `12 / 25 / 40` 档位时附加欢呼文案，并触发牌桌容器 `220ms` 轻幅震动（`±3px`）。
2. **通关波纹点亮**：末块落定 `200ms` 后，按对角线距离 `(x + y) * 45ms` 延迟，令全部彩色瓷砖依次执行 `380ms` 波纹弹起（`scale 1.18` + `translateY -8%` + 提亮 `1.25×`），同步从牌桌底边喷出 `40` 片像素画色系彩纸（持续 `1.1～1.8s`）。
3. **撤销立回动效**：撤销时被恢复的骨牌施加 `0～120ms` 随机微延迟，以 `scale 0.4 → 1.1 → 1.0` 弹性立回原位，提供清脆的「一键重排」反馈。

## 5. 五层渲染流水线与内存控制

与 [04_技术架构与开发手册](04_《推倒一幅画》技术架构与开发手册_v0.1.0.md) §6.1 对齐，每帧固定 5 层绘制：

1. **Layer 0（离屏静态牌桌）**：暖色背景 + 木框绿呢点纹，仅初始化/尺寸变更重绘。
2. **Layer 1（离屏已落定像素画层）**：每块骨牌倒牌动画结束后立即将其彩色瓷砖绘制到此离屏画布，随后从活跃动画数组移除；撤销时对被恢复格 `clearRect`。
3. **Layer 2（站立骨牌层）**：遍历所有未倒且非空位格，从 `dominoCacheCanvas` 按 `drawImage` 批绘；若当前格正被按压，向下偏移 `2px` 并微缩 `0.94×`；滑动达阈值后叠绘半透明白色方向预览箭头。
4. **Layer 3（动态倒牌 + 对象池粒子层）**：绘制所有处于 `0～230ms` 倒牌过渡态的活跃骨牌，以及 `256` 槽固定容量粒子池（扬尘 + 通关彩纸，`swap-remove` 回收，运行期零对象分配）。
5. **Layer 4（HUD 与内联面板层）**：顶栏、连续关卡条、推力槽、连击浮字、首关/提示手指动画、底部工具栏、通关/失败内联面板。

## 6. 资产清单与包体预算

| 资产模块 | 制作与加载方式 | 预计资源量 | 压缩后体积预估 |
| :--- | :--- | :---: | :---: |
| **牌桌与三类基础骨牌 + 5 类进阶机关** | 运行时矢量离屏预烘焙（支持多套皮肤配色表） | 12 槽预烘焙 | **0 KB（代码生成）** |
| **皮肤装饰纹样（木纹 / 竹简 / 麻将 / 糖果等）** | 可选轻量平铺贴图（PNG-8，`64×64`） | 4～6 张 | ~12 KB |
| **UI 极简图标（音量 / 撤销 / 提示 / 重摆 / 手指）** | 单张 UI 小图集（`atlas_ui.png`，PNG-8） | ~16 帧 | ~10 KB |
| **连续关卡与像素画数据（首批 150 关）** | 紧凑字符矩阵 JSON（查统一十色调色板） | 150 关 | ~50 KB |
| **中文字体子集（界面常用字 + 全部画名）** | 离线裁剪子集或小游戏系统字体直绘 | 按需子集 | 0～60 KB |
| **总计** | — | — | **~72～132 KB** |

> [!NOTE]
> 全量视觉与 150 关画作数据总计不超过 **150 KB**，不足微信小游戏 `4 MB` 主包上限的 **4%**，可确保首开秒进与极低内存占用。
